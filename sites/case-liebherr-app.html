Designsystem 2.0

Overview

Replacing four legacy systems with one shared foundation.

Liebherr's digital landscape spans dozens of product sites, configurators, and customer-facing apps across 13 divisions. Each had grown its own component library, type scale, and color logic — creating drift, duplicated work, and a confusing experience for users moving between Liebherr products.

Designsystem 2.0 is a complete rebuild: a token-first architecture, a shared component layer for both web and native, and contribution guidelines that let internal product teams ship faster without breaking visual consistency.

  • Three-tier token system (primitive → semantic → component)
  • 120+ components covering web and React Native
  • Themeable across all 13 product divisions
  • Automated handoff via Tokens Studio & GitHub
The Challenge

How do you unify 13 divisions without flattening them?

The brief was deceptively simple: one design system to rule them all. The reality was politics, technical debt, and 13 product teams each protecting their own conventions.

The hardest part wasn't drawing components — it was negotiating naming, governance, and a contribution model that felt fair. We ran weekly sync sessions with division leads for the first three months, plus a public Figma library that anyone could comment on.

Constraints we worked with: existing brand evolution rollout (running in parallel), legacy CMS that couldn't be replaced, accessibility floor of WCAG 2.2 AA, and shipping in production within ten months.

The Approach

A token-first system, themed per division.

We split the system into three clear layers — primitives (raw values), semantics (intent), and components (assembled). This let us theme each division through semantic tokens without touching the components themselves.

Documentation lives in a public Storybook with live code, do/don't pairs, and embedded Figma frames. We treated docs as a product: they got the same review process as components.

  • Migrated 4 legacy systems into the unified library
  • Cut average ship time for new screens by ~40%
  • Published contribution guidelines and quarterly RFC process

Outcome

Powering 40+ products inside Liebherr.

Twelve months in, Designsystem 2.0 is live across 40+ products, with internal NPS from product teams sitting at +62. The bigger win is cultural: design and engineering finally share a vocabulary, and new product teams can ship a feature-complete MVP in weeks instead of quarters.

The system continues to evolve through a public RFC process — the goal was never to finish it, but to make it ownable.
